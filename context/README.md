# Project Context Map

This file is the main map of the `context/` folder. It does not repeat project context on its own; it shows what information is where and when to read it.

## Reading Order

### Read in Every Task

- `project-summary.md`: To understand what the project is, its scope, and current state.
- `rules-and-boundaries.md`: To apply valid boundaries and mandatory rules in every task.

### Read According to Task

- `goals.md`: When prioritizing, planning, strategizing, or assessing success.
- `decisions.md`: When making new decisions, questioning a previous decision, or if there is a possibility of contradiction.
- `resources/README.md`: If resources are to be added or resource-based review is to be performed.
- `resources/resource-index.md`: If searching for a specific PDF, table, image, link, audio, or video.

## Current Context Map

| Location | Contents | When to Read? |
|---|---|---|
| `project-summary.md` | Project definition, purpose, scope, tech stack, and current state | Every task |
| `goals.md` | Active goals, priorities, and success criteria | Planning and prioritization |
| `rules-and-boundaries.md` | Permanent rules, boundaries, prohibitions, and authority areas | Every task |
| `decisions.md` | Finalized decisions, justifications, and statuses | Before decision or change |
| `resources/README.md` | Resource system usage and management rules | Resource operations |
| `resources/resource-index.md` | Inventory of actual resources in the project | When searching evidence or resource |
| `resources/links.md` | Internet and online resource records | When external link is needed |

## Adding a New Context File

When adding a new context file:

1. Give the file a clear and understandable name.
2. State its purpose at the beginning of the file.
3. Add the file to this map.
4. Write what it contains and under what conditions it should be read in the map.
5. If the file is moved, renamed, its purpose changes, or it is deleted, update the map in the same operation.
